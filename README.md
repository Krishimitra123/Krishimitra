# KrishiMitra · ಕೃಷಿಮಿತ್ರ

A voice-first farming assistant for Kannada-speaking farmers. A farmer taps the mic, asks a question in Kannada, and hears the answer read back aloud: what to grow, how to prepare organic inputs, today's mandi prices, the weather, or what is wrong with a crop from a photo.

**Runner-Up, Krishimanthan 2026** (Malnad College of Engineering, 62 teams). Presented and demonstrated live to an audience of about 1,000 farmers at a state agricultural convention in Hassan.

## How a voice question is answered

```
Mic (Expo app) ──► POST /api/query
                    1. Speech-to-text        Sarvam AI (Kannada / English)
                    2. Intent detection      keyword rules over a Kannada–English farming glossary
                    3. Retrieval             pgvector similarity search over the knowledge base
                                             (gemini-embedding-001, 768-dim; local multilingual
                                             sentence-transformers model as a fallback)
                    4. Structured lookup     exact recipes for organic inputs (jeevamrutha, panchagavya…)
                                             and mulching plants from curated JSON
                    5. Answer                Mistral, falling back to Sarvam-105B and then Gemini on
                                             rate limits or errors; answers translated to the farmer's language
                    6. Text-to-speech        Sarvam AI voice
               ◄── answer text + audio
```

For crop recommendations, yield and profit figures are computed in Python from a reference table rather than generated by the LLM, so the numbers it speaks are not made up by the model.

## Features

- **Voice and text chat** in Kannada or English, with conversation history
- **Crop disease diagnosis** from a leaf photo (Gemini Vision, with Mistral as a fallback)
- **Mandi prices** from the data.gov.in (Agmarknet) API, with a bundled Karnataka price snapshot used when no API key is configured
- **Weather** for the farmer's district from Open-Meteo
- **Sign-in** with email or phone and a short onboarding for district, crops and language

## Project structure

```
backend/            FastAPI
  routers/          query, transcribe, tts, diagnose, market, weather, auth
  modules/          m1_voice · m2_nlp · m3_rag · m3_structured_kb · m4_diagnosis · m5_response

```

## Run locally

**Backend**

```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # fill in the keys below
python3 -m uvicorn main:app --reload --port 8000
python3 smoke_test.py           # checks imports, corpus files and env vars
```

Set up the database by running `backend/scripts/full_supabase_setup.sql` in the Supabase SQL editor.

**Mobile**

```bash
cd mobile
npm install
npx expo start
```

Point `EXPO_PUBLIC_API_BASE_URL` (see `mobile/.env.example`) at your backend.

## Environment variables (backend)

| Variable | Purpose |
|---|---|
| `SUPABASE_URL`, `SUPABASE_SERVICE_KEY` | Database, vector search and auth |
| `SARVAM_API_KEY` | Kannada speech-to-text, text-to-speech, translation and fallback LLM |
| `MISTRAL_API_KEY` | Primary LLM |
| `GEMINI_API_KEY` | Embeddings, image diagnosis and fallback LLM |
| `DATA_GOV_API_KEY` | Optional: live mandi prices |
| `RAG_SIMILARITY_THRESHOLD`, `RAG_TOP_K` | Optional retrieval tuning |

Deployment config for Render is in `render.yaml`.

## Current limitations

- Sign-in is in demo mode: the backend triggers a Supabase email code when it can, but always accepts the fixed code `123456` and returns it in the response. This must be replaced with real verification before production use.
- Crop yields and costs used for recommendations come from a static reference table, not live data.
- There is no separate safety or fact-checking pass on LLM answers beyond the retrieval grounding and a filter that removes chemical-input suggestions.
